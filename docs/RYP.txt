    → widget.action

รายการอื่นที่ is_active = true
    → widget.items[]

widget.items[].code
    = list_of_value.sub_code

widget.items[].filterType
    = list_of_value.code

widget.items[].label
    = list_of_value.name

widget.items[].value
    = COALESCE(countResult, 0)

 
 
 
Dynamic Processing Logic
1. Select List of Value
   WHERE search_key = 'RYP_SUMMARY_WIDGET'
   AND is_active = true
   ORDER BY seq ASC
2. ดึง Payment Transaction ล่าสุดของแต่ละกรมธรรม์
3. ใช้ Payment Transaction ร่วมกับ Due Date
   เพื่อหา resolvedLovCode ของแต่ละ policy_no
4. COUNT DISTINCT policy_no
   GROUP BY resolvedLovCode
5. LEFT JOIN:
   list_of_value.code = resolvedLovCode
6. ถ้าไม่พบข้อมูลให้ value = 0
7. ถ้า code = RYP_ALL:
   Map เป็น widget.action
8. ถ้า code <> RYP_ALL:
   Map เป็น widget.items[]
9. ใช้:
   code     → filterType
   sub_code → item code
   name     → label
   
   
 สำหรับ RYP Widget ตัวอย่างคือ:

1. User เปิดเมนู “ดูแลลูกค้า”
2. Frontend ตรวจพบว่าต้องแสดง RYP Widget
3. ตรวจ Permission RYP_VIEW
4. ถ้ามีสิทธิ์ จึงเรียก:
   GET /ms-after/v1/renewal-policy/widget
5. นำ Response มาแสดง Widget

ต่างจากแบบ EAGER:

Loading Type	การทำงาน
EAGER	เรียก API ทันทีเมื่อเปิดหน้าหรือเริ่มโหลด Application
LAZY	เรียก API เมื่อผู้ใช้เข้าถึง Section/Widget หรือเมื่อ Component ถูก Render
ON_DEMAND	เรียกเมื่อผู้ใช้กดปุ่มหรือทำ Action โดยตรง
