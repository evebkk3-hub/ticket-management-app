# Impact Analysis \(I/A Solution\)\- Agent Profile \(agentPicture on Redis\) \[R1\]\[Sell\_4\]

| **Overview** | Revise Logic store agent profile picture on cache |
| --- | --- |
| **Background / Pain Points** | ### **Background** Currently, the system stores agent profile pictures in Redis, which is a significant architectural misalignment with best practices. Redis is designed for caching lightweight key-value data, not for storing binary large objects (BLOBs) such as images. This contradicts the design outlined in the technical assessment, which does not recommend using Redis for persistent storage of media files.  ### **Pain Points** 1. **Potential Redis Failure** – Storing images in Redis significantly increases memory consumption, leading to possible performance degradation, evictions, or crashes. 2. **Scalability Concerns** – Redis is an in-memory database, and using it for storing images can quickly exhaust available memory, making it difficult to scale efficiently. 3. **Repeating TLI’s Pain Point** – TLI has previously expressed concerns about system stability due to improper Redis usage, and this implementation revives the same risk they wanted to avoid.  ### **Proposed Action** To resolve this issue, we need to create an internal change request (CR) to migrate profile pictures from Redis to Amazon S3. This will: - Improve system stability by keeping Redis focused on caching. - Optimize storage by leveraging S3’s scalable and cost-effective object storage. - Align with best practices outlined in the tech assessment. |
