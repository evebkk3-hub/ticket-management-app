ข้อสรุปสำหรับใส่ใน Design

Payment History List ต้องรองรับการค้นหาข้อมูลตามขอบเขต SELF, DIRECT_TEAM และ ALL_TEAM โดยอาศัยเจ้าของกรมธรรม์และข้อมูล Agent Hierarchy แต่ไม่ควรจัดเก็บ View Scope ไว้ในตาราง Payment History โดยตรง

ตาราง Payment History ต้องมีฟิลด์ที่สามารถระบุ Agent Owner ของกรมธรรม์ได้ และ Backend ต้อง Join กับ Agent Hierarchy เพื่อกำหนดรายการที่ผู้ใช้งานมีสิทธิ์มองเห็น

ดังนั้นคำตอบคือ ต้องรองรับแน่นอนใน Data Model และ Query Design แต่สิ่งที่ต้องเพิ่มใน Payment History คือ owner_agent_id/sales_id ไม่ใช่เพิ่มคอลัมน์ SELF, DIRECT_TEAM, ALL_TEAM ครับ

****ให้ทีมที่อ๋อย เรียก API TL Smart และ TL SMart ส่ง Notification ทันทีในเส้น API ไม่ใช่แบบ Trigger*****
TL Smart จะเป็นผู้ส่ง Notification ทันทีหลังจากได้รับผลลัพธ์จาก API (Real-time Notification) โดยไม่ใช้การ Trigger จาก Batch Job, Scheduler หรือ Event Trigger
Notification Flow
1. Team P'Aoy' calls TL Smart API.
2. TL Smart processes the request and sends the Notification immediately within the same API flow.
3. Notification must be sent in real-time (synchronous process).
4. No Scheduler, Batch Job, or Event Trigger mechanism is required.
